결론부터 말씀드리면, "동일한 핵심 코어(Single Core) 백엔드를 두고, 프론트엔드 UI/UX와 AI 프롬프트 모드만 분리하는 구조"가 개발 효율성, 유지보수, 그리고 서비스 확장성 면에서 압도적으로 유리합니다.

제품 사진에서 특허·매뉴얼·문서를 검색하고 내부 구조를 추론하는 **핵심 엔진(Vision VLM + RAG + 3D 메커니즘 추론 파이프라인)은 두 서비스 모두 100% 동일**하기 때문입니다.

동일한 코어를 바탕으로 교육용과 일반/전문가용을 어떻게 효율적으로 나눌 수 있는지 아키텍처 전략을 정리해 드립니다.

## 1. 코어 통합 + 모드 분리 아키텍처 구조

백엔드는 하나로 유지하되, 요청 시 **`mode: "educational"`** 또는 **`mode: "pro_reverse_engineering"`** 파라미터를 넘겨 AI 분석 레벨과 프론트엔드 시각화 방식만 다르게 처리합니다.

```
                  [사용자 사진 업로드 + 모드 선택]
                                │
                                ▼
         ┌─────────────────────────────────────────────┐
         │     통합 백엔드 코어 (Shared Core Engine)       │
         │  1. Vision VLM (외형 분석 & 부품 분할)          │
         │  2. Mech RAG (특허/매뉴얼/작동 원리 DB 검색)     │
         │  3. 메커니즘 추론 및 3D CAD/메시 생성 파이프라인 │
         └──────────────────────┬──────────────────────┘
                                │
                ┌───────────────┴───────────────┐
                ▼                               ▼
     [Educational JSON Payload]      [Pro Engine JSON Payload]
     - 작동 원리 설명 (물리/기계)      - 정밀 STEP / STL 파일
     - 단계별 분해 스토리텔링        - 3D 프린터 출력 공차 (0.2mm)
     - 기어비/원리 퀴즈 데이터        - 기성품 BOM (볼트/베어링 규격)
                │                               │
                ▼                               ▼
    ┌─────────────────────────┐    ┌─────────────────────────┐
    │  교육용 프론트엔드 (Edu)  │    │ 일반/전문가 프론트엔드    │
    │  - 인터랙티브 3D 인포그래픽 │    │ - 정밀 CAD 분해도 뷰어  │
    │  - 체험형 시뮬레이션/퀴즈   │    │ - CAD/3MF 파일 다운로드  │
    │  - STEM/교과 과정 연계    │    │ - 부품 구매 BOM 리스트   │
    └─────────────────────────┘    └─────────────────────────┘

```

## 2. 교육용 vs 일반/전문가용 기능 차이점 비교

| 구분 | 교육용 모델 (Edu Mode) | 일반/전문가 모델 (Pro Mode) |
| --- | --- | --- |
| **타겟 유저** | 초·중·고 STEM 학생, 기계/디자인 전공자, 전시관 | 하이엔드 키덜트, 복원가, 3D 프린팅 메이커 |
| **핵심 목적** | **"어떻게 작동하는가?"** (원리 이해 및 학습) | **"어떻게 똑같이 만들 것인가?"** (역설계 및 출력) |
| **내부 추론 결과** | 원리 중심 설명 (예: "크랭크축이 회전운동을 왕복운동으로 변환합니다") | 정밀 치수 및 구조 (예: "지름 6mm D컷 축, M3 나사 산 깊이 5mm") |
| **3D 캔버스 표현** | 색상별 부품 가시화, **작동 애니메이션(기어 회전 등)**, 원리 팝업 | **정밀 분해도(Exploded View)**, 단면 잘라보기(Section Cut), 유격 측정 |
| **부속 제공 자료** | **학습 리포트 PDF**, 원리 퀴즈, 실생활 응용 사례 | **STEP/STL 3D 파일**, 3D 프린팅 설정 가이드, 규격 부품 BOM |

## 3. 프론트엔드 분리 구현 방식 (2가지 접근법)

### 방식 A. 단일 앱 내 '모드 스위치' (추천: 빠른 검증 및 B2C)

* 하나의 웹 애플리케이션 내 상단에 **[학생/교육용] ⇄ [메이커/역설계용] 토글 스위치**를 제공합니다.
* 동일한 3D 캔버스 컴포넌트를 공유하면서, 교육용 모드일 때는 "원리 툴팁과 애니메이션"을 켜고, 역설계 모드일 때는 "치수 및 공차 슬라이더"를 켜는 방식입니다.

### 방식 B. 멀티 도메인 / 서브도메인 분리 (추천: B2B/B2G 교육 시장 진출 시)

* **일반용:** `app.yourdomain.com` (결제 및 3D 파일 다운로드 중심)
* **교육용:** `edu.yourdomain.com` (학교/기관 전용 LMS 연동, 대시보드, 학생 성취도 관리)
* 백엔드 API 서버는 하나로 유지하되, 프론트엔드 빌드만 별도로 관리하여 시장별 마케팅과 요금제(Subscription vs License)를 완전히 다르게 가져갑니다.

## 4. 실무 구현 팁: LLM 프롬프트 가이딩

백엔드에서 AI에게 분석을 요청할 때 `mode` 값에 따라 프롬프트를 다르게 부여하면 코어 변경 없이 결과를 최적화할 수 있습니다.

* **Edu Mode 프롬프트 예시:**
> "이 사진 속 제품의 작동 원리를 중학생도 이해할 수 있는 쉬운 비유와 함께 분석해 줘. 주요 부품 3가지의 명칭과 이들이 만들어내는 물리적 운동(회전, 왕복 등)을 초점으로 설명하고, 관련 퀴즈 질문 2개를 생성해 줘."


* **Pro Mode 프롬프트 예시:**
> "이 사진 속 제품을 3D 프린터로 역설계하기 위한 정밀 부품 사양을 파악해 줘. 각 부품의 결합 방식(Snap-fit, M3 Thread 등)과 FDM 프린팅 시 필요한 공차(0.15~0.2mm)를 감안한 CadQuery 파라메트릭 제이손(JSON) 스키마로 출력해 줘."
